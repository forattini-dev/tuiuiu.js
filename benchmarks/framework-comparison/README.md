# Runtime comparison

This workspace compares the production runtime behavior of Tuiuiu, Ink, and
direct ANSI output without adding JSX source code to the repository.

JSX itself is syntax that disappears during compilation. Ink therefore uses
`React.createElement`, the runtime representation generated by JSX. This keeps
the comparison focused on the meaningful architectural difference: Tuiuiu's
signals, renderer, layout, and delta output versus React, the Ink reconciler,
Yoga layout, and Ink's incremental renderer.

Direct ANSI output is a small handwritten reference, not a component-framework
competitor or a claim of the lowest possible byte output.

## Scenarios

- `localized`: the header and footer change while 24 worker rows remain stable.
- `full`: every worker row changes on every update.

Each framework runs in its own Node.js process with forced garbage collection
available. Framework order rotates between samples to reduce order bias. Both
Tuiuiu and Ink render incrementally with FPS throttling disabled.

Tuiuiu is measured through its compact v2 root entrypoint. Package export
budgets separately guard module-surface growth.

The runner measures:

- module loading;
- process start to first paint;
- sequential update latency at p50, p95, and p99;
- bytes and writes per update;
- synchronous update bursts;
- heap growth before collection and retained heap/RSS after collection.

## Running

From the repository root:

```sh
pnpm benchmark:frameworks:quick
pnpm benchmark:frameworks
```

Ink and React use a lockfile local to this private benchmark package. Running a
normal `pnpm install` at the repository root does not install competitor
dependencies.

The quick profile is intended for workflow smoke coverage. The full profile
uses seven isolated samples per framework and scenario.

Generated machine-specific reports are written to `results/latest.md` and
`results/latest.json`. They are intentionally ignored by Git.

The manual GitHub Actions performance job runs the quick profile on Linux,
Windows, and macOS and publishes each report in that job's step summary.

## Interpreting results

Only compare results created on the same machine, Node version, terminal size,
and benchmark revision. Local results are evidence for investigation, not a
marketing claim. A performance statement should be based on repeated runs
across Linux, Windows, and macOS with variance disclosed.
