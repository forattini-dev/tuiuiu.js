# Migrating from tuiuiu.js 1.x to 2.0

Version 2 is a clean architectural boundary. It does not ship v1 aliases or a
compatibility entrypoint. Migrate each concept to its single v2 owner.

## Entrypoints

| v1 import or concept | v2 replacement |
|---|---|
| root catch-all imports | small everyday root or the owning subpath |
| `tuiuiu.js/minimal` | `tuiuiu.js` and `tuiuiu.js/app` |
| `tuiuiu.js/hooks` | `tuiuiu.js/app` |
| `tuiuiu.js/primitives`, `/atoms`, `/molecules`, `/organisms`, `/templates` | `tuiuiu.js/ui` |
| `tuiuiu.js/experimental` | stable APIs in their owning v2 module |
| `tuiuiu.js/compat` | no replacement; migrate the underlying concept |

See the [import map](/core/imports.md) for the complete list.

## Components and state

Wrap stateful function components with `component()` so hooks belong to the
correct keyed instance.

```ts
import { Text, component, useState } from 'tuiuiu.js';

const Counter = component('Counter', () => {
  const [count] = useState(0);
  return Text({}, String(count()));
});
```

Use stable keys for reorderable siblings. Do not call a hook-owning component
as an unowned helper or store component state in a module-global registry.

## Keyboard interaction

Replace key-driven actions with semantic commands or shortcuts.

```ts
// v1
useInput((input, key) => {
  if (key.ctrl && input === 's') save();
});

// v2
useShortcut('ctrl+s', save, {
  id: 'document.save',
  title: 'Save document',
});
```

Use `useCommand()` plus `useCommandBinding()` when commands must be discoverable
or have multiple bindings. Use `useInteraction()` only for normalized low-level
editing/protocol input. Modes and targets replace hotkey scope stacks.

## Collections

Collection state is keyed by stable identity, not array index. Select values,
tab keys, menu item IDs, and completion IDs must remain unique across updates.
Tabs activate automatically by default; use `activationMode: 'manual'` when
focus should move without changing the active panel.

For custom collection controls, compose `createCollectionController()` and
`createCollectionBindings()` from `tuiuiu.js/interaction`.

## Overlays and modals

Replace overlay stacks and global modal booleans with one owned session.

```ts
import { Text } from 'tuiuiu.js';
import { openModal } from 'tuiuiu.js/ui';

const session = openModal({
  id: 'settings',
  title: 'Settings',
  content: Text({}, 'Preferences'),
});

const outcome = await session.closed;
```

For custom presentation use `getOverlayHost().open(spec)`. Close the returned
session rather than popping shared state. The app mounts the visual host.

## Prompts

Call `prompt.*` from `tuiuiu.js/interaction`. Inside an app the prompt uses the
app's overlay, focus, and interaction owners; outside an app it uses the ANSI
terminal adapter. Do not create a second readline or raw-mode owner.

Non-TTY prompts require an explicit default or reject with
`PromptNonInteractiveError`.

## Rendering and application handles

Replace mode-specific render functions and mutable rerender handles with one
render call:

```ts
const app = render(App, {
  screen: 'inline', // or 'fullscreen' / 'alternate'
  maxFps: 60,
});

await app.waitUntilExit();
```

The returned `AppHandle` owns exit, unmount, focus, commands, overlays, prompts,
contributions, output, and its runtime-scoped services. Signal changes schedule
renders automatically; there is no public `rerender()` method.

## Extensions

Replace host mutation or untyped plugin arrays with typed contribution slots.
Declare slots with `defineSlots()`, contribute through `app.contributions`, and
dispose the returned handle to remove exactly that contribution.
